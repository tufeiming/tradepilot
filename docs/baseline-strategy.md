# 基线策略：一分钟双均线信号

本文档定义 TradePilot 的第一套基线策略。后续策略应作为新的策略组件加入，不应在没有版本说明、
测试和回测依据的情况下直接改变本策略语义。

## 定位

- 组件名称：`double_ma_signal`
- 实现类：`DoubleMaSignalStrategy`
- 当前默认参数：MA10/MA20
- K线周期：1分钟
- 输出：`BUY` 买入关注、`SELL` 卖出关注
- 运行模式：仅通知

这不是完整的自动交易策略。它不读取账户、持仓、可用资金和当日成交，也不发出委托。

## 输入数据

策略接收所选数据源发布的 VeighNa `TickData`，通过 `BarGenerator` 聚合为一分钟K线。均线只使用
收盘价。腾讯 POC 历史接口没有完整 OHLC 时，历史K线的开、高、低暂时使用同一分钟收盘价填充，
但这不影响当前只使用收盘价的均线计算。

默认启动前至少加载 100 根已完成分钟线。每个标的拥有独立的 `ArrayManager`、均线状态和策略实例，
不同标的之间不共享指标。

## 指标定义

设第 `t` 根已完成一分钟K线的收盘价为 `C(t)`：

```text
Fast(t) = 最近 fast_window 根收盘价的算术平均值
Slow(t) = 最近 slow_window 根收盘价的算术平均值
```

默认参数：

```toml
[strategy]
name = "double_ma_signal"
fast_window = 10
slow_window = 20
```

配置必须满足：

```text
2 <= fast_window < slow_window
minimum_history_bars >= max(100, slow_window + 2)
```

## 信号规则

严格金叉产生 `BUY`：

```text
Fast(t-1) < Slow(t-1)
且
Fast(t) > Slow(t)
```

严格死叉产生 `SELL`：

```text
Fast(t-1) > Slow(t-1)
且
Fast(t) < Slow(t)
```

任一时点两条均线相等时不产生交叉信号。策略不会因为价格仍在均线上方或下方而重复通知，只有新的
严格穿越才会产生信号。

## 时间和生命周期边界

- 历史回放只用于预热指标，初始化阶段不发送历史信号。
- 策略正式启动后，只处理新完成的一分钟K线。
- 收到下一分钟 Tick 时，上一分钟K线才被视为完成。
- 午休和收盘会话结束时，数据源状态事件刷新最后一根已经完成的K线。
- 用户在一分钟尚未结束时停止程序，不会把当前半根K线强制完成，也不会据此产生信号。
- 时间统一使用 `Asia/Shanghai`。

## 通知与幂等

每个信号包含：

- 策略实例名称
- 标的代码
- BUY/SELL 方向
- K线时间
- 收盘价
- 快慢均线值
- 实际数据源名称

幂等键由“策略实例 + 标的 + 方向 + K线时间”组成。同一信号即使事件重复、通知重试或程序重启，
也只会成功发送一次。

## 明确不包含的交易语义

- `BUY` 不代表系统已经买入。
- `SELL` 不判断是否持仓，仅表示卖出关注点。
- 不处理 A股 T+1、100股整数手、涨跌停、停牌和可用资金。
- 不计算手续费、印花税、滑点和复权。
- 不做空，不产生 `SHORT` 或 `COVER`。
- 不调用 `buy`、`sell`、`short`、`cover` 或 `send_order`。

## 已知局限

双均线属于滞后型趋势指标，在震荡行情中可能频繁出现无效交叉。腾讯公开接口仅用于验证架构和通知
流程，不具备交易级稳定性。当前策略在进入模拟交易或实盘讨论前，必须先通过复权数据回测，并加入
手续费、滑点、T+1、整数手和风险控制约束。

## 基线变更规则

以下改动应创建新的策略组件名称，而不是静默修改 `double_ma_signal`：

- 改变交叉定义或允许等号触发
- 增加趋势、成交量、止损或持仓过滤
- 改变K线周期或使用盘中未完成K线
- 将信号直接映射为委托

单纯调整 `fast_window`、`slow_window` 属于同一策略的参数变化，但应记录配置并重新验证。
