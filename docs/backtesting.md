# 图形化回测与运行模式

TradePilot 直接复用 `vnpy_ctabacktester` 的官方 GUI、撮合引擎、绩效统计、K线买卖点图和参数优化，
不维护第二套回测界面或收益公式。回测与实时监控是两个独立入口：

```powershell
uv run tradepilot backtest   # 历史研究和模拟成交
uv run tradepilot monitor    # 实时提醒，当前禁止下单
```

项目固定使用 `pandas==2.2.3`。官方回测 GUI 和 PyQtGraph 尚不兼容 Pandas 3 的整数标签索引语义，
升级 Pandas 前必须先通过图表回归测试。

## 场景：从零验证长期回测流程

这个场景面向第一次拿到项目、还不了解 VeighNa 的使用者。目标是确认下面整条链路能够运行：

```text
腾讯日线 -> 分页下载 -> SQLite 入库 -> 双均线预热和交叉
         -> VeighNa 模拟撮合 -> 绩效统计 -> 图表展示
```

它不依赖 A股正在开盘，也不需要飞书或券商账号。它适合做安装验收、GUI 演示和修改策略后的冒烟
测试；不适合评价一分钟策略是否盈利，也不能作为实盘依据。

### 1. 准备环境

以下命令在项目根目录执行。示例使用 Windows PowerShell：

```powershell
uv sync --python 3.13 --all-groups
Copy-Item config.example.toml config.toml
```

Linux 下第二条命令使用 `cp config.example.toml config.toml`。只运行历史回测时不需要飞书，确认本地
`config.toml` 至少包含下面的配置：

```toml
[data_source]
name = "tencent"
poll_interval_seconds = 3.0
stale_after_seconds = 30.0

[monitor]
symbols = ["515080.SSE"]
minimum_history_bars = 100

[strategy]
name = "double_ma_signal"
fast_window = 10
slow_window = 20

[execution]
mode = "notify"

[feishu]
enabled = false
```

关闭飞书只影响通知，不会关闭回测。不要把真实 webhook 提交到 Git。

### 2. 启动 GUI

```powershell
uv run tradepilot backtest
```

正常情况下会直接打开“CTA回测”窗口。这个命令使用项目本地 `.vntrader` 目录，数据库文件位于
`.vntrader/database.db`，不会写入用户主目录。

### 3. 首次下载长期日线

在窗口左侧填写：

| 字段 | 值 |
|---|---|
| 本地代码 | `515080.SSE` |
| K线周期 | `d` |
| 开始日期 | `2019/12/27` |
| 结束日期 | 最近一个已经收盘的交易日 |

点击“下载数据”，等待日志出现 `515080.SSE-d历史数据下载完成`。腾讯接口每次最多返回 640 根，
TradePilot 会自动向前分页；截至 `2026-07-24` 应有约 1592 根，未来数量会继续增加。这里的验收
标准是数据量明显超过 1000 且起止日期正确，不要求数量永远等于 1592。

同一范围可以重复下载，VeighNa 会按“标的、交易所、周期、时间”更新数据，不会不断创建重复K线。
已经下载过日线时可以跳过这一步。

### 4. 运行回测

继续在左侧填写：

| 字段 | 值 | 原因 |
|---|---:|---|
| 交易策略 | `DoubleMaLongBacktestStrategy` | A股/ETF 多头模拟策略 |
| 本地代码 | `515080.SSE` | 与下载数据一致 |
| K线周期 | `d` | 使用长期日线，不是只有 5 日的 `1m` |
| 开始日期 | `2020/07/01` | 保留上市初期数据给均线预热 |
| 结束日期 | 与下载结束日期一致 | 避免请求数据库中不存在的未来数据 |
| 手续费率 | `0` | 流程测试先排除交易成本 |
| 交易滑点 | `0` | 流程测试先排除滑点 |
| 合约乘数 | `100` | 一手按 100 份 ETF 计算 |
| 价格跳动 | `0.001` | ETF 最小价格变化 |
| 回测资金 | `100000` | 流程测试基准资金 |

点击“开始回测”。策略参数使用：

```text
fast_window = 10
slow_window = 20
history_size = 100
fixed_size = 1
t_plus_one = true
```

### 5. 判断流程是否成功

满足以下现象即可认为流程已经打通：

- 日志显示历史数据量大于 1000，而不是 `0`。
- 日志依次出现“策略初始化完成”“历史数据回放结束”和“策略统计指标计算完成”。
- 中间统计区域显示回测日期、总交易日和模拟成交笔数。
- 净值、回撤、每日盈亏和盈亏分布图正常显示。
- “成交记录”和“K线图表”可以打开；产生交叉时能看到模拟成交与买卖位置。

收益率正负、成交次数多少都不是这个场景的验收条件。它们会随结束日期和策略参数变化。

### 6. 常见问题

| 现象 | 原因和处理 |
|---|---|
| 配置提示缺少飞书 webhook | 只做回测时设置 `[feishu] enabled = false` |
| 仍然只有约 5 个交易日 | 选择了 `1m`；长期流程测试应选择 `d` 并重新下载 |
| 历史数据量为 `0` | 先点“下载数据”，并检查代码、周期、日期和网络访问 |
| 总滑点接近或超过总亏损 | 流程测试把滑点设为 `0`，不要沿用界面默认的 `0.2` |
| 图表出现 `KeyError: 0` | 执行 `uv sync --python 3.13 --all-groups`，不要把 Pandas 升级到 3 |
| 修改代码后界面行为没有变化 | 完全关闭旧 GUI，再重新执行 `uv run tradepilot backtest` |

测试完成后不需要删除数据库。下次只需把结束日期改为最近完整交易日并再次点击“下载数据”，即可
补充或刷新日线。

## 运行模式边界

```toml
[execution]
mode = "notify"
```

配置模型预留三种稳定模式：

| 模式 | 当前状态 | 含义 |
|---|---|---|
| `notify` | 可用且为默认值 | 实时产生信号并发送飞书，不产生委托 |
| `paper` | 预留 | 未来接入仿真账户；当前 `monitor` 启动前拒绝 |
| `live` | 预留 | 未来接入真实券商；当前 `monitor` 启动前拒绝 |

`backtest` 不读取该模式来决定是否下单。它只能创建 VeighNa 的 `BACKTESTING` 引擎，并将所选
数据源 Gateway 包装为只读研究 Gateway；模拟委托不会进入 `MainEngine.send_order`，任何手工真实
委托也会在研究进程内被拒绝。腾讯 Gateway 自身仍有第二层拒绝保护。

## 其他回测操作

完成上面的流程验收后，可以查看净值、回撤、每日盈亏、委托、成交和“K线图表”中的买卖点。
“参数优化”可以比较不同 `fast_window`、`slow_window`，但在正式研究中必须保留样本外数据再次验证。

ETF `515080.SSE` 的流程验证起始值可使用：

| 字段 | 建议值 | 说明 |
|---|---:|---|
| 百分比手续费 | `0` | POC 先排除成本；正式研究必须填写真实费率 |
| 滑点 | `0` | POC 先排除滑点；正式研究必须加入 |
| 合约乘数 | `100` | 策略一手按 100 份计算 |
| 价格跳动 | `0.001` | ETF 最小价格变化 |
| 回测资金 | `100000` | 仅作为研究基准 |

策略参数：

- `fast_window=10`、`slow_window=20`：与实时基线一致。
- `history_size=100`：指标预热长度，不应低于慢均线窗口加 2。
- `fixed_size=1`：每次模拟买入一手；实际金额由合约乘数决定。
- `t_plus_one=true`：同日出现 SELL 时延迟到下一交易日再模拟卖出，可关闭做对比实验。

## 共用规则与隔离执行

`DoubleMaStrategyBase` 负责K线、指标预热和严格金叉/死叉判定。实时类固定使用完整一分钟K线，只把
交叉发布为 `SignalEvent`；回测类按 GUI 选择的周期运行，只在 `EngineType.BACKTESTING` 下把相同
交叉转换为多头模拟委托。这样参数优化不会复制或悄悄修改实时信号公式，同时回测委托代码也不会
进入实时策略类。

官方回测器还会加载 `vnpy_ctastrategy` 自带策略。官方 `DoubleMaStrategy` 会多空反转，属于期货语义；
A股/ETF 基线应选择 `DoubleMaLongBacktestStrategy`。

## 当前数据限制

腾讯公开接口的一分钟数据仍只有最近约 5 个交易日，且只有可靠的分钟收盘价。TradePilot 为兼容
VeighNa K线对象暂时使用同一价格填充开、高、低、收，这会影响模拟撮合的真实性。

为了验证更长的回测链路，腾讯 Gateway 同时支持前复权日线 `d`，每页最多 640 根并自动向前分页。
`515080.SSE` 可覆盖从 `2019-12-27` 上市到最近完整交易日的 OHLCV。日线成交额字段不可用，保存为
零。日线长区间适合检查下载、入库、预热、信号、模拟成交和图表，不等价于一分钟策略回测，也不能
证明当前策略有效。

进入参数选择或实盘讨论前，应换用支持长周期复权分钟线的数据源，并按实际品种补齐手续费、滑点、
涨跌停、停牌和成交量约束。`paper/live` 只有在独立执行层、券商 Gateway、仓位核对和风险限制全部
完成后才会开放。
