# 15分钟图形化回测

TradePilot 复用 `vnpy_ctabacktester` 的官方 GUI、撮合、统计、净值图和K线成交图，并在项目层增加
明确的 `15m` 数据周期。以下流程不依赖 A股正在开盘，也不需要飞书或券商账户。

第一次接触项目、还没有安装环境或创建配置时，请先阅读
[15分钟策略从零运行指南](15m-quickstart.md)。本文只保留回测专题步骤。

## 1. 准备

在项目根目录执行：

```powershell
uv sync --python 3.13 --all-groups
Copy-Item config.example.toml config.toml
```

只做回测时可在本地 `config.toml` 设置：

```toml
[strategy]
name = "double_ma_signal"
bar_window_minutes = 15
fast_window = 10
slow_window = 60

[feishu]
enabled = false
```

本地真实配置和 `.vntrader` 已被 Git 忽略。已有 webhook 时不必关闭飞书；回测本身不会推送信号。

## 2. 打开界面

```powershell
uv run tradepilot backtest
```

窗口会直接打开 VeighNa 的“CTA回测”组件。TradePilot 已把默认代码设为配置中的第一个标的，并在
官方周期选项中加入 `15m`。

## 3. 下载约半年 15 分钟数据

左侧填写：

| 字段 | 建议值 |
|---|---|
| 本地代码 | `515080.SSE` |
| K线周期 | `15m` |
| 开始日期 | `2026/01/01` |
| 结束日期 | `2026/07/24`，或最近一个已收盘交易日 |

点击“下载数据”。日志应类似：

```text
515080.SSE-15m开始下载历史数据
515080.SSE-15m历史数据下载完成，数据量：1904，范围：2026-01-26 09:30 至 2026-07-24 14:45
```

腾讯只返回当前仍保留的数据，所以开始日期早于 2026-01-26 不会补出更旧分钟线。数据写入
`.vntrader/tradepilot_history.db`；重复下载按唯一键更新，不会重复累加，也不会和 VeighNa 的 `1m`
数据混在一起。

## 4. 运行 SMA10/SMA60 回测

下载完成后填写：

| 字段 | 值 | 说明 |
|---|---:|---|
| 交易策略 | `DoubleMaLongBacktestStrategy` | A股/ETF 多头模拟类 |
| 本地代码 | `515080.SSE` | 必须和下载代码一致 |
| K线周期 | `15m` | 必须和下载周期一致 |
| 开始日期 | `2026/02/09` | 给开始日前留出至少 100 根预热数据 |
| 结束日期 | `2026/07/24` | 或已下载的最后日期 |
| 手续费率 | `0` | 第一次只验证流程 |
| 交易滑点 | `0` | 第一次只验证流程 |
| 合约乘数 | `100` | ETF 一手按 100 份模拟 |
| 价格跳动 | `0.001` | ETF 最小价格变化 |
| 回测资金 | `100000` | 研究基准资金 |

点击“开始回测”后会出现策略参数对话框，确认：

```text
fast_window = 10
slow_window = 60
history_size = 100
bar_window_minutes = 15
fixed_size = 1
t_plus_one = true
```

点击参数对话框的“确定”，等待回放完成。

## 5. 看哪些结果

流程打通应满足：

- 日志显示“15分钟历史数据加载完成”，数据量明显大于 100，而不是 0。
- 随后出现“策略初始化完成”“历史数据回放结束”和统计计算完成。
- 中间区域显示总交易日、成交笔数、收益和回撤。
- “成交记录”可查看模拟开平仓，“K线图表”可查看对应买卖位置。
- 净值、回撤、每日盈亏和盈亏分布图能正常渲染。

本次目标是验证数据下载、预热、交叉、模拟撮合和图表整条链路。收益正负和成交次数不能证明策略
科学。第一次验证建议成本设为 0；正式研究必须换成真实手续费和滑点。

## 常见问题

| 现象 | 原因和处理 |
|---|---|
| 数据量为 0 | 先选择同一代码和 `15m` 点击“下载数据”，并检查网络和日期 |
| 只有约 5 个交易日 | 选成了 `1m`；重新选择 `15m` 下载 |
| 回测开始即未就绪 | 开始日期太靠近数据最早日期，向后调整到至少留出 100 根预热K线 |
| 图表 `KeyError: 0` | 运行 `uv sync --python 3.13 --all-groups`，保持 `pandas==2.2.3` |
| 修改代码后无变化 | 完全关闭旧 GUI，再重新执行启动命令 |
| 15m 参数优化被拒绝 | 当前只开放 15m 单次回测，先在参数对话框手工调整后分别运行 |

## 运行边界

`uv run tradepilot monitor` 执行实时盯盘，只通知且禁止下单；`uv run tradepilot backtest` 只使用
历史数据和模拟委托。研究 GUI 包装了只读 Gateway，回测委托不会进入真实 `MainEngine.send_order`。

腾讯六个月数据会滚动消失，建议每天收盘后打开 GUI，把结束日期改为最近交易日并再次点击“下载
数据”。需要两三年以上 15 分钟回测时，应实现另一个 `HistoricalBarService` 数据源组件，而不需要
修改策略或官方回测引擎。
